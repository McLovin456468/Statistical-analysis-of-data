# Проект: Статистический анализ данных сервиса аренды самокатов

## 1. Назначение и цель проекта

Сервис аренды самокатов предоставляет данные о пользователях из нескольких городов, их поездках и типах подписки. Необходимо проанализировать данные и проверить гипотезы, которые помогут бизнесу увеличить количество пользователей с подпиской и оптимизировать операции.

**Цель проекта:** исследовать поведение пользователей с подпиской и без, оценить их вклад в выручку, проверить статистические гипотезы.

---

## 2. Условия тарифов

| Тип подписки | Абонентская плата (мес.) | Стоимость минуты | Стоимость старта |
|--------------|--------------------------|------------------|------------------|
| Без подписки (free) | 0 руб. | 8 руб. | 50 руб. |
| Ultra | 199 руб. | 6 руб. | 0 руб. (бесплатно) |

## 4. Этапы выполнения

### 4.1. Загрузка данных
- Загрузить три CSV-файла в датафреймы.
- Вывести первые строки и общую информацию о каждом датафрейме.

### 4.2. Предобработка данных
- Привести столбец `date` к типу `datetime`.
- Создать столбец с номером месяца на основе `date`.
- Проверить пропуски и дубликаты во всех датафреймах. Обработать при наличии.

### 4.3. Исследовательский анализ данных

Выполнить визуализацию и описание:

- **Частота встречаемости городов** — распределение пользователей по городам.
- **Соотношение пользователей** — доля с подпиской Ultra и без подписки.
- **Возраст пользователей** — распределение, выбросы.
- **Расстояние за одну поездку** — распределение (метры).
- **Продолжительность поездок** — распределение (минуты).

### 4.4. Объединение данных
- Объединить `users_go`, `rides_go` и `subscriptions_go` в один датафрейм с помощью `merge()`.
- Создать два отдельных датафрейма:
  - пользователи **без подписки** (free);
  - пользователи **с подпиской** (ultra).
- Визуализировать распределение расстояния и времени поездок для обеих категорий.

### 4.5. Подсчёт выручки

**4.5.1. Агрегация поездок**
- Создать датафрейм с агрегированными данными для каждого пользователя за каждый месяц:
  - суммарное расстояние;
  - количество поездок;
  - суммарное время (минуты).

**4.5.2. Расчёт выручки**
- Добавить столбец с помесячной выручкой от каждого пользователя.
- **Правила расчёта:**
  - продолжительность каждой поездки округляется **до следующего целого числа** (ceil):
    - 25.3 → 26, 25.5 → 26, 26.0 → 26.
  - Для `free`: выручка = старт (50 руб.) + минуты × 8 руб.
  - Для `ultra`: выручка = минуты × 6 руб. (старт бесплатно) + абонентская плата (199 руб.) учитывается отдельно или включается в выручку за месяц.

### 4.6. Проверка гипотез

**Задача:** увеличить количество пользователей с подпиской. Перед проведением акций необходимо проверить следующие гипотезы.

#### 4.6.1. Гипотеза 1: Продолжительность поездок
- **Формулировка:** пользователи с подпиской тратят больше времени на поездки, чем пользователи без подписки.
- **Данные:** исходные данные о продолжительности каждой сессии (отдельно для подписчиков и free).
- **Метод:** статистический тест для независимых выборок.

#### 4.6.2. Гипотеза 2: Среднее расстояние за поездку
- **Формулировка:** среднее расстояние, которое проезжают пользователи с подпиской за одну поездку, **не превышает 3130 метров** (оптимальное расстояние с точки зрения износа самоката).
- **Метод:** односторонний тест (проверка, что среднее ≤ 3130 м).

#### 4.6.3. Гипотеза 3: Помесячная выручка
- **Формулировка:** помесячная выручка от пользователей с подпиской выше, чем от пользователей без подписки.
- **Метод:** тест для сравнения двух выборок (подписчики vs free) по месяцам.

#### 4.6.4. Гипотеза 4: Обращения в техподдержку (теоретическая)
- **Сценарий:** техническая команда обновила сервера. Есть данные о количестве обращений каждого пользователя **до** и **после** обновления.
- **Вопрос:** какой статистический тест применить?
- **Ответ:** тест для **связанных (парных) выборок** (например, парный t-критерий или Wilcoxon).

### 4.7. Необязательное задание: Распределения

#### 4.7.1. Промокоды на бесплатный месяц
- **Условия:** после бесплатного пробного периода подписку продлевают **10%** пользователей.
- **Цель:** разослать промокоды так, чтобы вероятность не выполнить план (менее 100 продлений) была **~5%**.
- **Задача:** подобрать параметры распределения (биномиальное или его аппроксимация), построить график, определить минимальное количество промокодов.

#### 4.7.2. Push-уведомления
- **Условия:** уведомления открывают около **40%** получивших.
- **План:** разослать **1 млн уведомлений**.
- **Задача:** с помощью аппроксимации построить график распределения, оценить вероятность того, что уведомление откроют **не более 399 500 пользователей**.

## 6. Примечания

- Продолжительность поездки при расчёте стоимости округляется **до следующего целого** (функция `ceil`).
- При проверке гипотез необходимо указать:
  - нулевую (H₀) и альтернативную (H₁) гипотезы;
  - выбранный статистический критерий и его обоснование;
  - уровень значимости (например, α = 0.05).
- Для гипотезы о среднем расстоянии (≤ 3130 м) используется односторонний тест.
